# 站点总表

「无聊而vibe的小游戏」系列的所有线上站点。2026-10-05 统一为同一种部署方式，在这里集中登记。

一键检查全部站点：

```bash
npm run check:sites
```

也可以只查某几个：`npm run check:sites -- stay dot`。脚本在 `scripts/check-sites.mjs`，加新站点时这张表和脚本里的 `SITES` 一起改。

## 统一规则

- **部署**：全部是 Cloudflare Pages 连 GitHub，**推送到 `main` 就自动构建上线**，不用手动部署。构建镜像 v3。
- **域名**：每个站点两处配置缺一不可——
  1. Pages 项目的「自定义域」里加上 `xxx.xiaoming6680.link`；
  2. xiaoming6680.link 的 DNS 里加一条代理 CNAME：`xxx` → `<项目名>.pages.dev`（橙色云开启）。
  - 同账号下 Pages 也不会自动加这条 DNS，要手动加。本机 wrangler 的登录令牌没有 DNS 权限，DNS 只能在 Cloudflare 面板里改。
- **HTTPS**：证书由 Cloudflare 自动签发；http 会 301 跳到 https。
- **不要开**的区域级优化（会影响别关我）：Rocket Loader、HTML 压缩 / 删注释、Web Analytics 自动注入。别关我有两关靠 `index.html` 里的注释，而且它承诺不收集任何数据。
- **不该上线的东西**：别关我的 `docs/`（完整剧透）、`tests/` 只能留在仓库里，构建产物 `dist/` 里没有它们；`check:sites` 会确认这些路径在线上是 404。

## 加一个新游戏

1. 新建本地目录和 GitHub 仓库，推送 `main`。
2. Cloudflare → Workers 和 Pages → 创建 Pages 项目，连接这个仓库，填构建命令和输出目录。
3. 项目「自定义域」里加 `新前缀.xiaoming6680.link`，再去 DNS 加代理 CNAME `新前缀` → `<项目名>.pages.dev`。
4. 在本仓库 `content/games.json` 加一项（上线后 `status` 写 `live`），推送后入口里就多一盒卡带。
5. 在 `scripts/check-sites.mjs` 的 `SITES` 和上面的表格里各加一行，跑一次 `npm run check:sites`。
6. README 的「卡带里有什么」表格加一行；需要的话跑 `node scripts/readme-shots.mjs` 更新配图。
7. 新游戏的 README 按统一结构写（见下）。

## README 统一结构

四个仓库的 README 都面向玩家、图文并茂、保持简短，开发内容一律放 `docs/`：

1. 标题 + 一句话（引用块）
2. 头图（`docs/images/`，真实画面截图，JPG 每张约 300KB 以内）
3. 一行：**▶ 在线玩：链接** · 建议设备 · 一局时长
4. 这是什么（2–3 句）
5. 玩起来是这样（几张配图，每张一句说明）
6. 怎么玩（操作表 + 要点）
7. 更多小游戏（指向铭刻和其他游戏）
8. 末尾一行指向 `docs/`

## 已知情况

- **微信**：xiaoming6680.link 没有备案，在微信里点开可能提示「非微信官方网页」，要手动选继续访问。别关我检测到聊天软件内置浏览器时，会提示复制链接到 Edge / Chrome 打开。
- **国内访问**：Cloudflare 免费版在国内没有节点，打开会偏慢，偶尔不稳定。
- **从一个点开始**发布的是整个仓库根目录，`docs/`、`tools/` 在线上也能访问（仓库本身是公开的，原会话判断无害）。
- **总入口、节拍幸存者、从一个点开始**没有 404 页：不存在的路径会返回首页（Pages 的默认行为）。只有别关我加了 `404.html`。
- **新建子域名后本机可能暂时打不开**：在 DNS 记录加上之前访问过的话，宽带运营商的 DNS 会把「不存在」缓存最多 30 分钟（xiaoming6680.link 的否定缓存时长）。用 1.1.1.1 / 8.8.8.8 能解析就说明没问题，等缓存过期即可。
- 2026-10-05 别关我从 Workers 静态资源迁到 Pages；旧 Worker `dont-close-me` 已删除（同名的 Pages 项目是现在在用的）。
